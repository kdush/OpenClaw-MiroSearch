# 安全策略

## 支持范围

当前以 `main` 与 `dev` 分支的最新版本为主要维护对象。

## 漏洞报告

若发现安全问题，请**不要**在公开 Issue 中披露细节。请通过私下渠道报告，并包含以下信息：

- 受影响的模块与文件路径
- 复现步骤
- 影响范围评估
- 建议修复方案（如有）

**首选报告渠道：**[GitHub Security Advisories](../../security/advisories/new)

## 安全默认值

- 不得向仓库提交真实密钥、令牌、密码或其他秘密信息。
- 使用 `.env` 文件管理敏感配置，提交时仅使用占位符。
- 新增外部依赖时，评估其许可证与安全风险。
- 验证所有外部输入，并显式处理边界条件与错误。
- API 默认采用 fail-closed 策略。未配置 `API_TOKENS` 且 `AUTH_DISABLED != 1` 时，受保护端点返回 `503`。
- `AUTH_DISABLED=1` 是仅限本地开发使用的显式鉴权绕过。生产或共享部署必须配置高强度 `API_TOKENS`，并保持鉴权启用。

## 密钥泄露处置

若怀疑密钥已泄露：

1. 立即在提供方控制台吊销旧密钥。
1. 生成替代密钥，并更新相关 `.env` 文件。
1. 检查日志与 API 请求记录，确认是否存在异常活动。
1. 轮换可能通过已泄露密钥暴露的下游秘密信息。
