# 全局审查问题修复设计

## 背景

本轮修复针对当前 `fix/global-review-remediation` 工作区中已经稳定复现的问题，
重点覆盖最终总结、模式参数、API/Gradio 执行契约与部署一致性。现有未提交修改属于
本轮工作基础，必须原样保留并在其上增量修改。

## 目标

1. 最终总结必须看到按配置保留的真实工具结果，且总结指令不占用工具结果名额。
2. 无有效总结时任务不得伪装成成功；降级正文必须通过质量字段如实暴露。
3. Pipeline 统一返回映射协议，所有调用方不再依赖旧四元组。
4. API 接收、执行、缓存和状态回报使用同一组有效参数。
5. 研究模式负责资源硬预算，输出篇幅负责呈现策略，篇幅不得突破模式硬上限。
6. Gradio 的本地/API 后端选择、缓存和调用方取消语义保持一致。
7. Anthropic 与 OpenAI 使用相同的分阶段模型和 token 路由语义。
8. Fail-closed 鉴权保留，但测试、Compose 示例和文档必须明确选择安全模式或开发模式。

## 方案比较

### 方案 A：逐调用点打补丁

只在当前报错位置补条件判断，例如总结前不 `pop()`、CLI 改为字典访问、缓存键多传
两个参数。优点是改动小；缺点是参数归一化、消息分类和结果质量仍分散，之后很容易在
API 与 Gradio 两套入口再次漂移。

### 方案 B：建立小型跨模块契约（采用）

- 给内部消息增加仅供 MiroFlow 使用的类型标记，只有明确标记的工具结果参与裁剪；
  发送给第三方 SDK 前移除内部标记。
- Pipeline 结果继续使用字典，并统一携带 `status`、总结正文、质量和错误信息。
- 请求进入执行层前只归一化一次，后续缓存、存储、队列与状态接口全部使用有效值。
- Hydra override 明确采用“篇幅默认值先应用，模式硬预算后应用”的优先级。

优点是修复根因、接口可测试，改动仍局限在现有模块；缺点是需要同步修改多个调用方和
回归测试。

### 方案 C：重写统一运行时

把 Gradio、API、CLI 全部迁移到同一个新服务对象，并重构消息和配置模型。长期最干净，
但对当前脏工作区风险过大，也超出本轮修复范围。

## 详细设计

### 1. 消息保留与总结

- 工具执行结果写入历史时添加内部类型标记。
- `_remove_tool_result_from_messages()` 只裁剪带工具结果标记的消息。
- 返回给 OpenAI/Anthropic SDK 的副本移除内部标记，原始历史仍保留完整审计信息。
- 最终总结直接追加总结指令，不删除最近工具结果。
- `keep_tool_result=0` 仅省略真实工具结果，不得省略总结、校验或格式修复指令。
- 总结重试次数使用独立配置，默认沿用既有重试常量，不再与工具保留数耦合。
- 最后一轮无工具响应时，在追加总结指令前执行一次上下文保护。

### 2. 总结状态与质量

- `OutputFormatter` 只把闭合的 `\boxed{...}` 判为格式有效。
- AnswerGenerator 将最终质量随总结一起返回。
- Pipeline 结果使用 `result_quality` 字段；Worker 为兼容旧结果可读取旧 `quality`，
  但新结果只写标准字段。
- 完全没有模型正文且没有可用中间结果时返回 `failed`；有正文但缺 boxed 时允许
  `completed`，同时 `format_valid=false`、`fallback_used=true`。

### 3. Pipeline 返回协议

- `execute_task_pipeline()` 保持字典返回值。
- CLI、benchmark、Gradio 和 Worker 均按键读取，不再做位置解包。
- 对必要键使用显式默认值或失败分支，避免协议缺失时静默成功。

### 4. 模式与请求参数

- API 数值契约与实际支持范围一致：检索条数仅允许 10/20/30，校验轮次为 1..8。
- 请求字段省略时，先读取部署环境默认值，再归一化。
- Router 在计算缓存键、创建任务和入队之前生成一份有效参数，之后不再保存原始歧义值。
- 输出篇幅 override 先加入，模式 override 后加入，使模式预算成为硬上限。
- API 与 Gradio 使用相同优先级并增加矩阵测试，特别覆盖 `quota+detailed`。

### 5. Gradio 后端、缓存与取消

- 本地结果缓存键包含检索条数和校验轮次。
- `BACKEND_MODE=api` 的非流式公开入口必须调用 api-server，而不是本地 Pipeline。
- 公开入口显式绑定 `caller_id`，按调用方取消不得退化为全局取消。
- 本地执行不跨并发任务复用带 `task_log`/浏览器会话的 ToolManager；缓存仅保存不可变
  配置与工具定义。

### 6. Provider 与部署

- Anthropic 根据 `agent_type` 选择 main/tool/fast/thinking/summary 模型与对应 token 上限，
  与 OpenAI 行为对齐。
- 保留未配置鉴权即拒绝的安全默认；本地 Compose 示例显式设置开发模式，
  生产暴露说明要求关闭开发模式并配置匹配的服务端/客户端 Token。
- API 测试公共 fixture 显式选择开发模式，鉴权专项测试自行覆盖环境。

## 测试策略

- 每个根因先增加最小失败测试并确认红灯，再实现最小修复。
- 总结链路覆盖 compact/balanced/detailed、`keep_tool_result=0`、最新工具证据、
  空总结和缺 boxed。
- 模式矩阵至少覆盖 quota/research × compact/detailed。
- API 集成测试验证请求、任务元数据、Worker override 三层值一致。
- Gradio 测试验证缓存键、API 后端分流和 caller 隔离。
- 最终运行四个项目测试套件及相关 lint。

## 非目标

- 不重写整个运行时。
- 不更换现有 LLM SDK。
- 不改变搜索 Provider 排序策略。
- 不执行 Git commit、push 或 PR。
